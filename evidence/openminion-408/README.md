# OpenMinion #408: storage tests close the SQLite connections and the API runtime they own

Evidence for the fix PR of [#408](https://github.com/openminion/openminion/issues/408) (branch `fix/408-windows-test-connection-close`, head `8e666e17`, on `dev` @ `8b220e14`). The change is test-only: in the twelve tests named in #408 and their helpers, read connections use `closing(...)`, write connections use `closing(...) as conn, conn:`, and `test_runtime_bootstraps_storage_schema` closes its `APIRuntime` before the temporary directory is removed. The original report and its probe are in [`openminion-windows-test-cleanup`](../openminion-windows-test-cleanup).

Files:
- `windows-12-dev.log`, `windows-12-head.log`: native Windows 11, CPython 3.11.11, SQLite 3.47.1, the 12 test ids of #408, 5 runs on a clean worktree of `dev` @ `8b220e14` and 5 on the branch head. `dev`: 11 failed, 1 passed every time; branch: 12 passed every time.
- `windows-six-dev.log`, `windows-six-head.log`: the six targets from #408 (the four storage files, `tests/storage/test_storagectl_cli.py` and `APIRuntimeBootstrapTests`), 5 runs each. `dev`: 14 failed, 69 passed, 3 skipped every time; branch: 2 failed, 81 passed, 3 skipped every time. The 2 left are the `storagectl restore` tests, whose open connection is storagectl's own record store; that is reported separately as [#412](https://github.com/openminion/openminion/issues/412) (evidence [`openminion-storagectl-restore-target`](../openminion-storagectl-restore-target)).
- `run-linux-focus.log`, from `run408.sh`: Ubuntu 24.04 GitHub-hosted runner with PostgreSQL 16 (AliceMessi/linux-runner run 40190204361). The 12 tests (3 runs) and the six targets on the branch head and with `dev`'s tests (`git checkout 8b220e14 -- tests`): all pass on both, since Linux allows deleting or replacing an open file. Also `tests/storage/test_migrations_runner.py` with `-m postgres` (it carries a module-level `postgres` marker, so `make test-ci` deselects it), the #412 probe, `ruff check .`, `make format-check`, `make workflow-check`, `make lint` and `make test-critical`.
- `run-linux-testci.log`: the full `make test-ci` on the branch head: 1 failed, 20231 passed, 29 skipped, 1326 deselected. The failure is `test_unreachable_db_raises_with_redacted_url`, a 60 s timeout.
- `run-linux-dev-pg-timeout-test.log`: that test alone on a fresh checkout of `dev` @ `8b220e14`. It times out the same way when the `postgres` extra (psycopg) is installed, as in the runs above, and passes without it. It connects to the unroutable `192.0.2.1`, so it depends on the environment, not on the branch.

The Windows logs keep the failing lines and the summary of each run; paths are shortened to `<checkout>`, `<python>` and `<tmp>`, and the localized Windows error text is trimmed.
